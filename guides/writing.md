# 글쓰기 원칙

> **읽는 시점**: 본문 문장을 새로 쓰거나 고칠 때. 기준 환경(Java 21, Spring Boot 3, MySQL 8 등)은 루트 `CLAUDE.md`에 있습니다.

## 독자와 깊이
- 독자는 **신입~주니어 백엔드 개발자**입니다. "개념을 설명할 수 있고, 실무에서 알아볼 수 있는 깊이"까지만 씁니다.
- 본문을 어렵게 만드는 정확성 보강은 본문에 넣지 않고 **"지금은 넘어가도 되는 것" 상자**로 보냅니다.
  - 예: 04편의 하이퍼스레딩·vCPU 설명
  - 예: 02편의 이스케이프 분석
- 초심자에게 너무 깊은 배경 설명은 넣지 않습니다. 예: 13편에서 RSA 키 교환이 제거된 이유는 뺐습니다.

## 표준과 구현을 구분하는 말투
문단마다 태그를 붙이지 않고, **문장 안에 조건 문구**를 넣어 적용 범위를 드러냅니다.
- "스프링 기본 설정에서 …" (프록시 모드, 트랜잭션 범위 영속성 컨텍스트, OSIV 기본값)
- "InnoDB에서 …", "MySQL은 …, PostgreSQL은 …"
- "HTTP/1.1·2 기준이며, HTTP/3은 …"
- "JDK 21~23에서는 …"

조건은 관련 규칙이 모인 곳의 **첫 문장에 한 번만** 붙이고, 규칙마다 반복하지 않습니다. 예: 20편은 "스프링은 기본 설정에서 …" 뒤에 규칙 세 가지가 이어집니다.

## 단정 피하기
- "항상", "절대", "모두", "쓸모없어진다" 같은 표현은 조건을 확인한 뒤에만 씁니다.
- 숫자 예시에는 조건을 붙입니다.
  - "회원이 모두 다르면 총 101번"
  - "메모리가 허락하는 만큼 (수십만 개도 가능)"
  - "경험에서 나온 출발점일 뿐, 부하 테스트로 정함"
- 교육용 모델을 쓸 때는 모델이라고 밝힙니다. 이때 **"그래도 동작 결과는 같다"**처럼 독자가 모델을 믿어도 되는 범위까지 함께 말합니다(02편 스택/힙).
- 입문 문장을 단순하게 쓰고 뒤 절에서 정확히 보완한다면, 앞 문장에 이어짐 표시를 붙입니다. 예: "(정확히 어디에 걸리는지는 3절)"
- 시리즈의 끝이나 전체 편수를 전제하는 표현("마지막 편입니다", "N편을 지나오며")은 쓰지 않습니다. 편 수는 계속 늘어납니다.

## 용어
- 새 용어는 처음 나올 때 한 문장으로 정의합니다. 예: 25편 "Primary는 원본 DB이고, Replica는 …"
- 영어 원어가 헷갈릴 수 있으면 병기합니다. 예: "피닝, pinning", "HOL(Head-of-Line) 블로킹"
- 한 편 안에서는 용어를 통일합니다. 예: 04편은 "코어"로 통일하고, 정확한 단위(vCPU)는 상자에서 설명합니다.

## 편 사이 연결
- 앞 편을 참조할 때는 "(NN편)" 또는 "NN편에서 본 …"으로 씁니다.
- 반복되는 원리는 연결 키워드로 묶습니다. 사이트의 연결 키워드 지도와 `README.md`의 지도는 **똑같이** 유지합니다(괄호 힌트 포함).
- 연결 키워드: 풀링·재사용 / 공유 상태·동시성 / 대기·블로킹 / 캐시·지역성 / 무상태·스케일아웃 / 장애 전파·타임아웃 / 일관성 트레이드오프 / 프록시 함정

## 근거
- 사실 관계는 공식 문서와 명세를 기준으로 판단합니다(RFC, JDK·Spring·MySQL·HikariCP 문서).
- 외부 리뷰의 지적도 근거와 대조해서 수용·유지를 정합니다. 과한 지적은 근거를 남기고 유지합니다.
