네트워크 계층 큰 그림

이제 서버 밖으로 나갑니다. 네트워크는 여러 계층이 각자 한 가지 일만 맡아 쌓여 있는 구조입니다. OSI 7계층 이름을 외우는 것보다, 에러가 났을 때 어느 계층의 문제인지 짚을 수 있는 것이 실무에서 훨씬 쓸모 있습니다.

1계층마다 맡은 일이 다르다

택배를 생각해 보면 쉽습니다. 내용물(HTTP 요청)을 상자에 넣고, 받는 사람 호수(포트)를 쓰고, 건물 주소(IP)를 쓴 송장을 붙여, 트럭(케이블·와이파이)에 싣습니다. 받는 쪽은 반대 순서로 뜯습니다.

계층맡은 일백엔드에서 보이는 것
애플리케이션무엇을 주고받을지 (의미)HTTP 메서드·상태 코드, DNS 이름
전송어느 프로그램에게, 빠짐없이 순서대로포트 번호(8080, 3306), 연결, 타임아웃
인터넷어느 컴퓨터로, 어떤 경로로IP 주소, 보안 그룹·방화벽 규칙
링크바로 옆 장비까지 전달백엔드 개발자가 직접 다룰 일은 거의 없음

IP는 건물 주소, 포트는 호수입니다. 한 서버(IP) 안에서 스프링은 8080, MySQL은 3306, Redis는 6379 호수에 삽니다. 연결 하나는 "내 IP·포트 ↔ 상대 IP·포트" 네 값의 조합으로 구분됩니다(11편).

2L4와 L7: 로드밸런서가 어디까지 보나

실무에서 계층 번호가 가장 자주 나오는 곳은 로드밸런서입니다. OSI 기준으로 전송 계층이 4번(L4), 애플리케이션이 7번(L7)이라 이렇게 부릅니다.

3실무 예시

장애 대응

에러 메시지로 어느 계층 문제인지 짚기

외부 API나 DB 호출이 실패했을 때, 예외 메시지만 보고도 어디서 막혔는지 좁힐 수 있습니다. 아래쪽 계층부터 통과해야 위쪽으로 올라갈 수 있다는 점을 떠올리면 됩니다.

예외 / 메시지막힌 단계먼저 볼 것
UnknownHostExceptionDNS: 이름 → IP 변환 실패도메인 오타, 내부 DNS 설정 (10편)
Connection refusedIP까지는 갔지만 그 포트에 받는 프로그램이 없음포트 번호, 상대 서버가 떠 있는지
connect timed out상대에게 닿지 못함 (응답 자체가 없음)방화벽·보안 그룹, 라우팅
SSLHandshakeException연결은 됐지만 TLS 협상 실패인증서, 신뢰 저장소 (13편)
Read timed out연결·요청은 됐는데 응답이 늦음상대 서버 성능, 타임아웃 설정 (16편)
HTTP 4xx / 5xx통신은 성공, 애플리케이션이 거절·실패요청 내용, 상대 서버 로그 (12편)

특히 refused와 timed out의 차이가 중요합니다. refused는 "문 앞까지 갔는데 아무도 없음"이라 빨리 실패하고, connect timed out은 "문까지 가는 길이 막힘"(주로 방화벽)이라 타임아웃만큼 기다린 뒤 실패합니다.

실수 예시

로그에 찍힌 클라이언트 IP가 전부 로드밸런서 IP다

L7 로드밸런서나 프록시는 클라이언트와 연결을 한 번 끊고 자기가 새로 서버에 연결합니다. 그래서 서버 입장에서 연결 상대(request.getRemoteAddr())는 항상 로드밸런서입니다. IP 기반 접근 제한이나 로그 분석이 전부 틀어집니다.

✓ 프록시가 남긴 헤더로 원래 IP 확인
X-Forwarded-For: 203.0.113.7, 10.0.1.12   // 맨 앞이 원래 클라이언트

# Spring Boot: 신뢰하는 프록시의 헤더를 반영하도록 설정
server:
  forward-headers-strategy: native

이 헤더는 클라이언트가 위조할 수도 있으므로, 신뢰하는 프록시가 붙인 값만 믿도록 인프라와 함께 설정합니다.

실수 예시

서버가 고장 났는데 헬스 체크는 정상이다

L4 헬스 체크는 "8080 포트에 TCP 연결이 되는가"만 봅니다. 애플리케이션이 DB 연결을 모두 잃어 요청마다 500을 내도, 포트는 열려 있으니 정상으로 판단해 계속 트래픽을 보냅니다.

해결: L7 헬스 체크로 /actuator/health 같은 경로를 호출해 HTTP 200 응답까지 확인합니다. 다만 헬스 체크에 외부 의존성을 너무 많이 넣으면, 외부 서비스 하나의 장애로 모든 서버가 동시에 빠지는 반대 문제가 생기니 범위를 신중히 정합니다.

설계 이유

계층을 나누면 바꿀 수 있는 것이 생긴다

HTTP/1.1에서 HTTP/2로 바꿔도 TCP·IP는 그대로이고, 와이파이에서 유선으로 바꿔도 HTTP 코드는 그대로입니다. TLS(13편)가 HTTP와 TCP 사이에 끼어들어 암호화를 추가할 수 있는 것도 계층이 나뉘어 있기 때문입니다. 코드에서 인터페이스로 구현을 감추는 것과 같은 원리입니다.

4설명해보기

답을 열기 전에 먼저 소리 내어 설명해 보세요.

IP 주소와 포트는 각각 무엇을 구분하나요?
IP 주소는 네트워크 상의 어느 컴퓨터인지, 포트는 그 컴퓨터 안의 어느 프로그램인지를 구분합니다. 같은 서버에서 스프링은 8080, MySQL은 3306처럼 포트로 나뉩니다.
L4와 L7 로드밸런서의 차이, 그리고 경로별 라우팅은 어디서 가능한가요?
L4는 IP와 포트만 보고 연결 단위로 분배하고, L7은 HTTP 요청의 경로·헤더·쿠키까지 읽고 분배합니다. /api와 /admin을 다른 서버로 보내는 경로 기반 라우팅은 HTTP를 해석하는 L7에서만 가능합니다.
Connection refused와 connect timed out은 각각 무엇을 의심하게 하나요?
refused는 상대 컴퓨터에는 닿았지만 그 포트에서 기다리는 프로그램이 없다는 뜻이라 서버가 꺼졌거나 포트가 틀렸을 가능성이 큽니다. connect timed out은 응답 자체가 오지 않은 것이라 방화벽·보안 그룹·라우팅처럼 가는 길이 막힌 경우를 의심합니다.
로드밸런서 뒤의 서버에서 클라이언트 IP를 알려면?
프록시는 자기가 서버에 새로 연결하므로 연결 상대 주소는 로드밸런서 IP입니다. 로드밸런서가 붙여 주는 X-Forwarded-For 헤더에서 원래 IP를 읽고, 스프링의 forward-headers-strategy 설정으로 신뢰하는 프록시 헤더를 반영합니다.
